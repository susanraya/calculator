<!-- sdlc:auto:start overview -->
calculator is a scaffolded full-stack app generated by the Quorq AI SDLC platform: an approved React 19 + Vite single-page frontend that currently renders seeded sample data, paired with a FastAPI 0.115 backend that has no business logic yet beyond a health check (no architecture had been approved for it when generated). The backend uses SQLAlchemy over SQLite by default (Postgres 16 is the approved target, swappable via DATABASE_URL), and Postgres is available locally via docker-compose. The two apps are not yet wired together; frontend/src/lib/api.ts is the prepared seam for calling the real API.

<!-- sdlc:auto:start setup -->
1. Clone the repository
2. Copy .env.example to .env and fill in any required values
3. cd backend && pip install -r requirements.txt
4. (optional) from the repo root, run `docker-compose up -d` to start the Postgres 16 database
5. cd frontend && npm install

<!-- sdlc:auto:start conventions -->
- Backend organizes endpoints into one router per approved architecture component (backend/app/routers)
- Every generated backend route returns a typed StubResponse placeholder until implemented
- SQLAlchemy models all inherit from the shared Base in app/database.py; tables are created via Base.metadata.create_all on startup (no migrations yet)
- Backend reads configuration from environment variables: DATABASE_URL (defaults to local SQLite) and ALLOWED_ORIGINS (comma-separated CORS origins, defaults to the Vite dev server)
- Frontend reads VITE_API_BASE_URL and VITE_API_SECRET_KEY at build time to target the deployed API and send a bearer token; currently unused by the generated screens, which render seeded sample data
- Frontend component tests live beside the components they test, under src/, matched by vitest's `src/**/*.{test,spec}.{ts,tsx}`; Playwright e2e specs live separately in e2e/
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Frontend requests to the backend are blocked by CORS | Set ALLOWED_ORIGINS on the backend to include the frontend's origin, or run the frontend on the default Vite dev ports (localhost:5173 / 127.0.0.1:5173) which are allowed by default |
| Backend can't find a Postgres database | The backend defaults to a local SQLite file (app.db) when DATABASE_URL is unset, so it runs without Postgres; set DATABASE_URL to point at the docker-compose Postgres instance (postgresql://app:app@localhost:5432/app) if you need Postgres |
| npm run build succeeds but tsc fails | The build step does not typecheck; run npm run typecheck separately to catch TypeScript errors before deploying |
| npm run test:e2e fails because no browser is installed | Run npm run test:e2e:install first to fetch Chromium |
| bare `pytest` run from repo root can't import app | Run pytest from the backend/ directory, where pytest.ini sets pythonpath=. so `import app` resolves |
